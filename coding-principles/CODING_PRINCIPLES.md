# 코딩 원칙

다음 원칙은 새 스킬, 자동화, 보조 스크립트, 문서 분석 기능을 만들거나 수정할 때 우선 적용한다. 사용자의 현재 요청이나 상위 지침과 충돌하면 그 지시를 우선한다. 이 파일은 단일 정본이며, 사용자가 코딩 원칙의 업그레이드·수정·교체를 요청하면 새 내용으로 덮어쓴다.

“완벽한 이식”은 근거 없는 보장이 아니라, 합의된 대상 환경에서 설치·실행·검증·복구가 재현 가능하다는 증거로 판정한다. 확인하지 못한 환경은 지원된다고 주장하지 않는다.

## 1. 우선순위·범위·설계

- 사용자 요청, 상위 정책, 프로젝트의 기존 지침을 먼저 확인하고, 충돌 시 우선순위와 가정을 명시한다.
- 목표, 범위, 비목표, 성공 기준, 위험 요소, 완료 조건을 구현 전에 작은 검증 단위로 나눈다.
- Codex 전용 구현에 묶지 않고, 가능한 경우 표준 Agent Skills 호환 공용 코어로 설계한다.
- 한 에이전트에 기능을 묶지 않는다. 필요한 에이전트가 같은 스킬을 독립적으로 사용할 수 있게 한다.
- 스킬마다 독립 폴더와 `SKILL.md`를 둔다.
- `SKILL.md`에는 선택 기준, 핵심 제약, 짧은 흐름만 둔다. 조건부·형식별 상세 지침은 `references/`, 반복적이고 결정적인 작업은 `scripts/`로 분리한다.
- 필요한 참조만 단계적으로 읽게 하여 불필요한 토큰 사용과 컨텍스트 오염을 줄인다.

### 유지보수 가능한 폴더 경계

- 최상위 폴더는 기능·도메인 단위로 나눈다. 특정 에이전트, 일회성 작업, 개인 컴퓨터 이름을 기준으로 공용 기능을 분류하지 않는다.
- 각 스킬 폴더는 해당 기능의 단일 소유 경계다. 다른 스킬의 파일을 복사해 중복 유지하지 말고, 정말 공유해야 하는 코어만 별도 공용 폴더·명확한 인터페이스로 분리한다.
- 파일은 역할에 맞는 폴더에 둔다. 지침은 `SKILL.md`, 조건부 설명은 `references/`, 실행 자동화는 `scripts/`, 테스트와 테스트용 입력은 `tests/`, 결과물에 포함할 원본 자산은 `assets/`를 사용한다. 필요 없는 폴더·빈 폴더·추측성 템플릿은 만들지 않는다.
- 소스, 사용자별 설정·비밀값, 임시 파일, 테스트 산출물, 영구 결과를 서로 다른 경계에 둔다. 생성물은 소스 트리에 섞지 않고, 추적 여부와 보존·정리 정책을 명확히 한다.
- 이름은 기능과 역할이 드러나게 일관되게 짓고, 경로가 변경되면 이를 참조하는 스킬·스크립트·테스트를 함께 갱신하고 검증한다.

### 계획 평가와 나노 단위 실행

- 구현 전에 계획 초안을 만들고, 목표·제약·환경·의존성·산출물·검증·복구를 성공 기준에 연결한다.
- 계획 자체를 객관적으로 검토한다. 잘된 점은 근거와 함께 인정하고, 실제로 발견된 부족함·모호함·위험만 지적한다. 억지 결함을 만들지 않으며, 평가 점수는 범위·추적성·실행 가능성·검증 가능성에 근거해 산정한다.
- 평가 결과로 계획을 보완한 뒤, 전체를 100% 기준선으로 하여 의존관계가 명확하고 하나씩 검증 가능한 나노 단위로 나눈다. 각 단위에는 완료 조건, 예상 산출물, 검증 방법, 실패 시 처리 방법을 둔다.
- 나노 단위 하나는 한 가지 관찰 가능한 동작 또는 한 묶음의 불가분 변경만 포함한다. 너무 커서 독립 검증할 수 없거나, 너무 작아 의미 있는 진척을 만들지 못하는 단위는 다시 조정한다.
- 각 단위에서 구현 → 정합성·오류·버그·회귀 검토 → 필요한 개선 → 검증 순서를 지킨다. 검증되지 않은 단위는 완료로 처리하지 않는다.
- 진행률은 검증을 통과한 완료 단위의 비중으로만 계산해 계획 대비 백분율로 보고한다. 추측·시간 경과·파일 생성만으로 진척도를 부풀리지 않는다.
- 범위·의존성·위험이 바뀌면 계획 기준선과 진행률을 갱신하고, 무엇이 왜 바뀌었는지와 기존 평가에 미치는 영향을 명시한다.

## 2. 구현 전 환경·이식성 사전점검

- 구현 또는 설치 전에 현재 환경과 목표 환경을 조사한다. 운영체제·배포판·버전, CPU 아키텍처, 셸·런타임, 패키지 관리자, 파일시스템·마운트, 경로·문자 인코딩, 네트워크·프록시, 디스크·메모리, 권한 모델을 확인한다.
- 필요한 외부 도구·라이브러리·모델·서비스에 대해 최소/권장 버전, 라이선스, 설치 출처, 실행 가능 여부, 상호 호환성을 표로 정리한다.
- 현재 환경과 목표 환경의 차이를 이식성 위험으로 등록하고, 지원·대체 경로·명시적 미지원 중 하나로 결정한다. 추측으로 호환된다고 간주하지 않는다.
- 개인 경로, 계정명, 임시 토큰, 특정 마운트 위치를 공용 코어에 하드코딩하지 않는다. 환경 변수·명시적 설정·런타임 어댑터로 분리하고, 안전한 기본값과 검증 오류를 둔다.
- 설치는 가능한 한 재현 가능하고 검증 가능해야 한다. 버전·체크섬·다운로드 출처를 기록하고, 이미 설치된 상태에서 안전하게 다시 실행할 수 있어야 한다.
- 권한 상승은 최후의 수단으로 하며 최소 권한만 요구한다. 설치·변경 전 필요한 권한과 영향 범위를 알리고, 불필요한 전역 설정은 만들지 않는다.

## 3. 구현 방식과 인터페이스

- 각 단위는 구현 후 계획과의 정합성, 오류, 예외 처리, 회귀 가능성을 검토한 뒤 다음 단위로 진행한다.
- 같은 역할의 함수·명령·도구 호출이 불필요하게 중복되지 않도록 호출 경로를 점검한다. 신뢰성 확보를 위한 의도적 이중 검증은 목적을 기록한다.
- 하나의 도구에 과도하게 의존하지 않는다. 도구별 강점과 입력 특성에 따라 책임을 분리하고, 실패·경고·대체 경로를 명확히 둔다.
- 입력·출력 형식, 경로, 종료 코드, 오류 메시지, 메타데이터의 계약을 명확히 한다. 공유 매니페스트·스키마·설정에는 버전을 두고, 호환되지 않는 변경은 감지하거나 이전 경로를 제공한다.
- 자동화는 안전하게 재실행할 수 있어야 한다. 기존 결과를 조용히 덮어쓰지 말고, 충돌 없는 새 출력 위치를 만들거나 명시적으로 중단한다.
- 시간·메모리·디스크·네트워크·비용 한계를 고려한다. 임시 자원은 성공·실패 모두에서 정리하고, 장시간 작업은 진행 상태와 중단 가능한 경계를 제공한다.

## 4. 원본·데이터·보안

- 원본 파일과 사용자 데이터를 기본적으로 수정·이동·삭제하지 않는다.
- 결과물은 요청한 위치에 저장한다. 문서 분석은 기본적으로 원본 또는 Drive에서 내려받은 로컬 사본 옆의 별도 분석 폴더에 저장한다.
- Google Drive 등 개인 문서의 일반 검색은 연결된 Drive를 먼저 사용한다. Drive 원본은 수정하지 않고, 로컬 도구가 필요하면 다운로드 폴더에 안전한 사본을 만든다.
- 영구 결과에는 출처, 도구·버전, 처리 시각, 진단 로그, 검증 결과를 남긴다. 가능하면 원본 해시로 분석 전후 동일성을 확인한다.
- 비밀값·인증 정보·임시 다운로드 URL·개인 식별 정보는 코드, 로그, 매니페스트, 커밋에 남기지 않는다. 로그는 문제 해결에 필요한 최소 정보만 기록한다.
- 암호화·비밀번호 우회·외부 업로드·권한 상승·원격 쓰기처럼 민감한 작업은 사용자의 명시적 요청과 범위 안에서만 한다.

## 5. 검증·이식 판정·복구

- 정적 검사만으로 끝내지 않는다. 실제 입력 또는 의미 있는 최소 사례로 핵심 경로를 검증한다.
- 단위·통합·종단 간 검증을 위험도에 맞춰 수행한다. 정상 입력뿐 아니라 누락된 의존성, 잘못된 권한, 손상된 입력, 재실행, 동시 실행, 네트워크 실패 같은 실패 경로도 확인한다.
- 이식 검증은 가능하면 깨끗한 대상 환경 또는 격리된 테스트 환경에서 설치부터 실행까지 다시 수행한다. 현재 개발 환경에서만 통과한 결과는 이식 완료의 증거가 아니다.
- 원본 보존, 출력 비어 있지 않음, 메타데이터 일치, 도구 설치 상태, 오류 시 종료 동작, 리소스 정리를 확인한다.
- 성공뿐 아니라 경고와 한계를 결과에 포함한다. OCR 신뢰도 저하, 파서 진단, 누락 가능성, 미검증 플랫폼은 숨기지 않는다.
- 변경 전에 복구 방법을 정하고, 실패 시 원본·기존 설정·사용자 데이터를 복구 가능한 상태로 남긴다. 되돌릴 수 없는 변경은 별도 확인 없이는 실행하지 않는다.
- 발견한 결함은 좁고 재현 가능한 수정으로 해결하고, 수정 뒤 같은 경로를 다시 검증한다.

## 6. 변경 관리와 전달

- 사용자가 허용한 범위의 파일만 변경한다. 기존의 관련 없는 변경은 보존한다.
- 커밋 전에는 변경 범위, 민감 정보 포함 여부, 실행 가능 파일의 권한, 자동 생성 산출물 포함 여부를 확인하고, 검증 가능한 단위로 커밋한다.
- 완료 보고에는 결과, 저장 위치, 지원·검증한 환경, 검증 근거, 남은 제한 사항과 복구 방법만 간결하게 알린다.
