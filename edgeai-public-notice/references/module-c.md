# C 모듈 — 상세 참여전략

## 목적

`ANALYSIS_PACKET`, `REPORT_PACKET`, 필요 시 `ORG_PACKET`을 바탕으로 실제 참여 포지션과 실행계획을 구체화한다. 전략은 새로운 사실을 만들지 않으며, 사실에 기반한 제안은 `전략상 추론`으로 표시한다.

## 전략 결정 순서

1. 법적·공고상 차단요건
2. 신청자격과 필수 증빙
3. 기술·제품·실적 관련성
4. 엣지에이아이 포지션 적합성
5. 외부기관 의존도와 역할 공백
6. 산출물 범위
7. 예산·자부담·일정
8. 증빙 확보 가능성
9. 내부 결정 및 제출 가능성

앞 단계의 차단요건이 해소되지 않으면 뒤 단계의 기술 강점만으로 전략을 상향하지 않는다.

## 필수 전략 출력

- 전략 요약
- 기존 판단과 전략 제안의 관계
- 권장 포지션과 전제조건
- 선택단위별 추진·조건부·보류·제외 판단
- 강점 활용 방향
- 약점·리스크별 합법적 보완 또는 포지션 조정
- 컨소시엄·외부기관 R&R
- 산출물별 자체수행·분담·외주·수요처 협조 범위
- 예산·자부담·일정 대응
- 증빙 확보계획
- 사업계획서·제안서 작성방향
- 실행 로드맵과 차단 리스크

## 보완전략 경계

“우회전략” 대신 “합법적 보완·포지션 조정 전략”을 사용한다. 포지션 변경, 공동연구, 공동수급, 외부기관 연계, 직접생산 보유사 활용은 공고상 허용 여부 확인 후에만 전략으로 제안한다.

다음은 보완전략으로 포장하지 않는다.

- 명확한 자격 미충족
- 마감 경과
- 지역 요건 미충족
- 공동수급 불가 공고
- 필수 인증·직접생산 요건의 마감 전 미충족
- 필수 제출서류 생략

## 기술 표현

AI 모델 경량화, 양자화, 프루닝, 온디바이스 포팅, NPU 적용, 비전 AI, 시스템 연동 등은 회사자료 또는 증빙에서 확인된 경우에만 확정 표현으로 사용한다. 하드웨어 IP·반도체 자체 설계·국산 NPU 하드웨어 개발 완료로 확장하지 않는다.

## 실행 로드맵

각 조치에 `action_id`, 담당자, 기한, 선행조건, 산출물, 미완료 시 처리방식을 기록한다. 기한이 자료에 없으면 임의 산정하지 않고 `[확인 필요]`로 표시한다.
