# 정본 모듈 맵

기존 프롬프트의 명칭 혼동을 막기 위해 다음 명칭을 canonical name으로 사용한다.

## A — 전체 공고 분석

입력: 공고문·정정공고·RFP·작성양식·평가기준·회사자료·재무자료·기관자료

출력:

- `FACT_PACKET`: 자료 원장과 공고·회사·기관의 확인 사실
- `ANALYSIS_PACKET`: 공고 유형, 핵심요건, 선택단위, 적합성, 강점, 약점, 리스크, 외부기관 필요성

A 내부 참조 위치:

- 기관 중요도 분류: A-11-1
- 기관별 기본 리스크: A-11-2
- 공고 핵심 요구사항: A-5
- 공고 유형: A-4
- 엣지에이아이 신청주체: A-7

기존 문서에서 “A 섹션 7-1” 또는 “A 섹션 3”을 기관·공고 핵심요건으로 참조하는 표현은 사용하지 않는다.

## A-2 — 외부기관 상세 분석

엣지에이아이를 제외한 실명 외부기관이 3개 이상일 때만 실행한다. A-11-1과 A-5를 입력으로 사용하며, A의 신청구조·포지션·핵심 산출물·수행기간·예산·회사 역량도 함께 참조한다.

출력: `ORG_PACKET`

- 기관 지위와 수행 역할
- 공고상 필요성
- 자격·역량·증빙 상태
- 엣지에이아이와의 보완·중복·공백
- 본문 반영 수준
- 허용 문안·금지 문안
- 보완자료와 판단 변경 조건

외부기관이 2개 이하이면 `A2_NOT_REQUIRED`를 기록한다. 3개 이상이나 자료가 부족하면 `A2_RESTRICTED`를 기록하고, 자료 없는 기관도 최소 리스크 레코드를 남긴다.

## B — 내부 의사결정 보고서

입력: `ANALYSIS_PACKET`, 필요 시 `ORG_PACKET`, 사용자 보고 지시

출력: `REPORT_PACKET`

- 1~2페이지 본문
- 핵심 결론
- 공고 개요
- 참여 적합성
- 핵심 강점·리스크
- 포지션·컨소시엄
- 즉시 조치
- 주장·근거 메타정보

본문 분량과 상세 근거·기관표·보완자료표는 분리한다.

## C — 상세 참여전략

입력: `ANALYSIS_PACKET`, `REPORT_PACKET`, 필요 시 `ORG_PACKET`

출력: `STRATEGY_PACKET`

- 참여 포지션
- 선택단위별 전략
- 강점 활용
- 약점·리스크 보완
- 합법적 보완·포지션 조정
- 기관 R&R
- 산출물 범위
- 예산·일정
- 증빙 확보
- 실행 로드맵

전략은 새로운 사실을 만들지 않는다. 사실에 기반한 전략적 추론은 `전략상 추론`으로 표시한다.

## D — 실제 문안 작성

입력: `STRATEGY_PACKET`, 작성양식, 평가기준, 확정 사용 가능 주장

출력: 사업계획서·제안서·검토보고서 문안

`REPORT_PACKET`의 결론이나 `STRATEGY_PACKET`의 제안을 임의로 상향하지 않는다. 선택단위·기관·산출물의 대상이 지정되지 않으면 문안을 확정하지 않는다.

## S — 스타일 후처리

입력: D 문안 또는 B 보고서, 스타일 참고문서

스타일 참고문서에서 추출하는 것은 제목, 도입, 문단 길이, 번호체계, 표 사용, 종결 방식뿐이다. S는 사실·판단·수치·조건·기관 역할을 변경하지 않는다.

## Q — 최종 품질검증

입력: 최종 문안, `FACT_PACKET`, `REPORT_PACKET`, `STRATEGY_PACKET`

확인 항목:

- 최신 공고·정정공고 적용
- 근거 위치와 주장 연결
- 조건부 판단 강도 보존
- 수치·일정·예산·기관 역할 검증
- MOU·LOI·계약·구매확약 구분
- 지원·입찰참가·수행·실증·선정·낙찰 구분
- 본문 사용 금지 주장 제거
- 분량·제출형식 확인
